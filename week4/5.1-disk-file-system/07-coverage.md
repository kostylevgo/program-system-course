# Этап 7. Проверка use cases

В условии нет акторов и пользовательских целей. По A4 введён внешний «Наблюдатель модели»: человек или программа, проверяющие существующее состояние. Он не становится предметным классом. Граница системы — модель файловой системы диска. Все сценарии ниже — проверочные, с чтением уже созданных объектов; создание и изменение не предполагаются.

## Пробелы черновика и исправления

| Код | Обнаружено при проверке | Решение и владелец | Повторная проверка |
| --- | --- | --- | --- |
| G1 | Структурный черновик не имеет операций для наблюдения. | Добавить Disk.findCluster, Disk.listFolders, Folder.listEntries, File.readData, Cluster.readContent по A4. | Каждый шаг таблицы ниже получил операцию. |
| G2 | Связь файла с несколькими кластерами не задаёт порядок восстановления данных. | У File.dataClusters указать {ordered, unique}, A5. | UC3 различает последовательности частей; один кластер не повторяется. |
| G3 | Для чтения содержимого нет представления полезной нагрузки. | Добавить Cluster.content: ByteSequence и контракт readContent(); список папки согласовать с subfolders/files, A5 и C5. | UC2 и UC3 могут получить логические данные. Кодирование остаётся вне уровня модели. |

Это расширение для проверки, а не новые требования R1–R4. Классы не добавлены; прохождение критериев подтверждено в 04-criteria.md. Черновик 06-draft.puml оставлен без изменений; дополнения внесены в final-class-diagram.puml и сводный каталог 05-relations.md.

## Основные сценарии и повторная проверка

| Use case → шаг | Класс и операция | Атрибуты и связи | Результат / изменение состояния | Итог |
| --- | --- | --- | --- | --- |
| UC1 → 1. Передать выбранному диску номер. | Disk.findCluster(number) | Disk.clusters, Cluster.number | Получен существующий кластер этого диска или отсутствие результата; состояние не меняется. | Покрыт, R1, C1. |
| UC2 → 1. Получить доступные папки выбранного диска. | Disk.listFolders() | Disk.folders; Folder.parent для выделения корней | Получена коллекция папок; выбор конкретной папки делает актор. | Покрыт, R2, A1–A2. |
| UC2 → 2. Запросить непосредственное содержимое выбранной папки. | Folder.listEntries() вызывает Cluster.readContent() для indexCluster | Folder.indexCluster, Cluster.content, Folder.subfolders, Folder.files | Получены ссылки на именованные папки и файлы, соответствующие списку в одном кластере, C5. | Покрыт, R2–R3, A5. |
| UC2 → 3. При выборе подпапки повторить шаг 2 для неё. | Folder.listEntries() | subfolders/parent, name | Просмотрена следующая папка; родительская структура и данные не меняются. | Покрыт, R2, C2–C3. |
| UC3 → 1. Прочитать выбранный файл. | File.readData() | File.dataClusters {ordered, unique} | Определена последовательность как минимум двух кластеров. | Покрыт, R4, C6. |
| UC3 → 2. Получить полезную нагрузку каждого кластера. | Cluster.readContent(), вызываемая File.readData() | Cluster.content, Cluster.disk; File.folder.disk | Получены части файла на том же диске, C3. | Покрыт, R4, A5. |
| UC3 → 3. Собрать части в заданном порядке. | File.readData() | Порядок dataClusters и результаты readContent() | Возвращены логические данные файла; состояние не меняется. | Покрыт, R4, A5. |

Предусловие UC1–UC2: актору известен рассматриваемый Disk. Предусловие UC3: выбран File, например в результате UC2. Это не делает UC2 обязательным вложенным сценарием UC3; include/extend не требуются. Отображение имени использует атрибут name и не требует отдельного метода. Чтение байтов внутреннего кластера — шаг доменной реализации, а не отдельная пользовательская цель.

## Альтернативы

- Исходный текст прямо допускает два вида содержимого: папки и файлы, R2. Они могут присутствовать вместе; UC2 возвращает оба вида.
- UC1: номер отсутствует — findCluster возвращает отсутствие результата. Это контракт проверочной операции по A4, а не ошибка, заданная условием.
- UC2: папок на диске нет — listFolders возвращает пустую коллекцию, A2.
- UC2: папка пуста — listEntries возвращает пустую коллекцию; её indexCluster всё равно существует, R3 и A2.
- UC2: у папки нет parent — это папка верхнего уровня, A1. Допускается несколько корней.
- UC3: два или больше кластеров — один алгоритм чтения, R4. Файлы в нуле или одном кластере не поддерживаются выбранной трактовкой.

Нехватка места, потеря кластера, ошибки чтения, обновления списка и запись файлов в тексте не описаны; сценарии для них не изобретаются.

## Покрытие требований и открытые границы

| Требование | Структурная реализация | Проверка |
| --- | --- | --- |
| R1 | Disk–Cluster, Cluster.number, C1 и C7 | UC1; кластер имеет ровно один диск. |
| R2 | Folder.name, File.name, Disk–Folder, две связи содержимого, C2 | UC2; смешанное содержимое и вложенность. |
| R3 | Folder.indexCluster ровно 1, C3 и C5 | UC2, шаг 2; у пустой папки также есть кластер списка. |
| R4 | File.dataClusters 2..*, C3 и C6 | UC3; чтение всех частей в порядке A5. |

Неразрешённых пробелов внутри принятых A1–A6 нет. Сам текст не позволяет подтвердить отсутствие ссылок и совместного использования кластеров, пустые диски, правила имён и физическое кодирование. Они обозначены как предположения или границы модели в 00-source.md. Для обычной файловой системы возможность файлов в 0 или 1 кластере потребовала бы уточнения R4, а не скрытой замены 2..* на 0..* или 1..*.

После этапов 8–9 повторная проверка не требует изменений: стереотипы не меняют операции; агрегаты и ограничения доступа не вводятся.
