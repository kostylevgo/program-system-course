# Этап 8. Типы классов

| Класс | Тип | Основание идентичности или ответственности |
| --- | --- | --- |
| Disk | Entity | Два носителя остаются разными объектами, даже если их содержимое полностью совпало, A6. Disk задаёт область владения кластерами и нумерации, R1. |
| Cluster | Entity | Физическая единица определяется парой (disk, number), R1 и A6. Кластеры с одинаковыми байтами на разных адресах различны; изменение content не меняет адресуемый объект. |
| Folder | Entity | Имя и список не определяют тождество: разные пустые папки с одинаковым именем могут находиться в разных местах. По A6 изменение содержимого не создаёт другую папку. Возможность такой мутации не означает добавления соответствующей операции в текущий интерфейс. |
| File | Entity | Имя и байты не определяют тождество: два файла могут иметь одинаковые значения, оставаясь разными объектами, A6. Размещение относится к конкретному файлу, R4. |

При сравнении Entity учитывается идентичность объекта, а не только равенство значений атрибутов. A6 явно отделяет это проектное решение от буквального текста. Служебные id не добавлены ради выбора типа.

String и Integer, а также ByteSequence (упорядоченная последовательность байтов с допустимыми повторами) — типы значений, а не дополнительные предметные Value-object-классы. Ни один из принятых классов не является Service, Repository или Factory. Наличие у Disk коллекций естественных частей и размещённых папок не делает его репозиторием: это собственное предметное состояние носителя. Создание объектов и отдельный процесс управления файловой системой не заданы.

Несовместимых ответственностей не выявлено. В итоговой диаграмме каждый класс отмечен стереотипом <<Entity>>.
