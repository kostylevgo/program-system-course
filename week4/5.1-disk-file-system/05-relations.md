# Этап 5. Атрибуты, методы и связи

## Преобразование понятий

| Понятие | Элемент модели | Владелец / участники | Основание |
| --- | --- | --- | --- |
| Номер | number: Integer | Cluster | R1. Уникален в пределах disk; начальное значение и непрерывность не заданы. |
| Имя папки | name: String | Folder | R2. Уникальность имён не предполагается. |
| Имя файла | name: String | File | R2. Расширение и полный путь не являются отдельными полями. |
| Список файлов и папок | subfolders, files; размещение в indexCluster | Folder, Folder, File, Cluster | R2–R3. Список — представление этих коллекций; отдельный объект List не нужен. |
| Данные файла | dataClusters; content: ByteSequence и readContent(); readData() | File, Cluster | R4. content и операции добавлены проверкой этапа 7, A4–A5. |
| Вложенная папка | Роли subfolders / parent | Folder | R2. Тот же класс, без дублирования. |
| Хранение / вложенность / состав | Именованные связи ниже | Соответствующие участники | Предикаты описывают структуру, а не процедуру. Основания для Service нет. |

ByteSequence — тип значения: конечная упорядоченная последовательность байтов, включая пустую; повторяющиеся байты допустимы. Он не является дополнительным предметным классом. Integer и String также являются типами значений. Коллекции ссылок представлены концами ассоциаций; дублирующих полей с теми же именами в блоках классов нет.

## Связи

Кратность у конца B — число B для одного A. Роль конца — имя свойства противоположного участника. Например, роль clusters находится у конца Cluster и означает Disk.clusters.

| Имя связи | A: роль и кратность у конца A | B: роль и кратность у конца B | UML-тип и обоснование | Источник |
| --- | --- | --- | --- | --- |
| Состоит из | Disk: disk, 1 | Cluster: clusters, 1..* | Композиция: кластер моделируется как физическая часть конкретного диска, не переносимая на другой носитель; без диска такой физической части нет. При освобождении данных кластер не уничтожается. | R1, A2 |
| Размещает | Disk: disk, 1 | Folder: folders, 0..* | Ассоциация размещения всех папок, включая вложенные; жизненный цикл папок условием не определён. | R2, A2 |
| Содержит подпапки | Folder: parent, 0..1 | Folder: subfolders, 0..* | Рекурсивная ассоциация непосредственной вложенности. Удаление родителя и судьба детей не описаны, поэтому композиция не утверждается. | R2, A1–A2 |
| Содержит файлы | Folder: folder, 1 | File: files, 0..* | Ассоциация содержимого; автоматическое удаление файлов вместе с папкой не предполагается. | R2, A1–A2 |
| Размещает список | Folder: indexOwner, 0..1 | Cluster: indexCluster, 1 | Ассоциация хранения: одна папка использует ровно один кластер списка; сам кластер принадлежит диску. | R3, A3 |
| Размещает данные | File: fileOwner, 0..1 | Cluster: dataClusters, 2..* | Ассоциация хранения: файл использует несколько кластеров. В итоговой модели dataClusters имеют {ordered, unique} по A5. | R4, A3, A5 |

Все кратности определены либо текстом, либо указанными предположениями. Неустановленных кратностей в выбранном варианте нет. В исходном условии не заданы: обратные кратности хранения, единственность родителей и допустимость пустого диска; решения по ним нельзя переносить на реальную файловую систему без проверки A1–A3.

Агрегация с пустым ромбом, наследование и зависимости не требуются. Disk—File выводится через File.folder.disk; отдельная связь избыточна.

## Операции после проверки этапа 7

Черновик этапа 6 сохраняет структуру без операций. Следующее дополнение относится к итоговой модели и документировано в 07-coverage.md.

| Операция | Данные и ответственность | Контракт | Источник |
| --- | --- | --- | --- |
| Disk.findCluster(number: Integer): Cluster[0..1] | clusters, Cluster.number | Возвращает кластер этого диска с указанным номером либо отсутствие результата. | R1, A4 |
| Disk.listFolders(): Folder[*] | folders | Возвращает все папки диска, включая вложенные; корневые выделяются по отсутствующему parent. | R2, A4 |
| Folder.listEntries(): (Folder \| File)[*] | indexCluster.content, subfolders, files | Возвращает непосредственные папки и файлы из списка, хранящегося в indexCluster. Пустой список допустим. | R2–R3, A4–A5 |
| Cluster.readContent(): ByteSequence | content | Возвращает логически значимую полезную нагрузку кластера без изменения состояния. | R3–R4, A4–A5 |
| File.readData(): ByteSequence | dataClusters с порядком, Cluster.readContent() | Собирает полезную нагрузку кластеров в порядке dataClusters. Физическое кодирование вне модели. | R4, A4–A5 |

Тип (Folder | File)[*] обозначает смешанную коллекцию ссылок, а не новый класс или иерархию наследования. Способ кодирования ссылок в кластере не определён. Все операции — запросы; транзакции записи и поддержание инвариантов при изменениях не входят в условие.

## Ограничения сверх кратностей

- C1 (R1): в одном Disk номера Cluster уникальны. На разных дисках они могут совпадать.
- C2 (R2, A1): связь parent/subfolders ациклична; parent не может ссылаться на саму папку. Корень имеет parent = отсутствует. Единственный общий корень не навязывается.
- C3 (R2–R4): Folder.indexCluster.disk = Folder.disk; у вложенной папки disk равен disk родителя; каждый File.dataClusters.disk равен File.folder.disk.
- C4 (A3): для любого Cluster число indexOwner + число fileOwner ≤ 1. Это исключает одновременно список папки и данные файла; две независимые кратности 0..1 сами такого запрета не дают.
- C5 (R3, A5): логическое декодирование содержимого indexCluster даёт в точности subfolders ∪ files, без пропусков и лишних элементов. Пустая папка также занимает один кластер списка. Вместимость списка в один кластер — инвариант условия; размер и формат кластера не заданы.
- C6 (R4, A5): dataClusters — упорядоченная коллекция различных кластеров; её размер не меньше двух. Привязка порядка появилась при проверке восстановления данных на этапе 7.
- C7 (R1): физическая принадлежность Cluster.disk неизменна в течение жизни кластера; освобождение содержимого не удаляет кластер из Disk.clusters.

Сериализация, проверка нехватки места, мутации и освобождение кластеров не моделируются: исходное описание не задаёт соответствующих действий.
