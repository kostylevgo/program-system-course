# Этап 3. Действия и ответственность

Исходный текст описывает состояние и устройство системы. В нём нет команды создать, удалить, записать или прочитать объект. Поэтому структурные предикаты не превращаются автоматически в методы изменения.

| Предикат | Источник | Участники | Владелец состояния / операции | Состояние и решение |
| --- | --- | --- | --- | --- |
| «состоит из» | R1 | Disk, Cluster | Disk владеет физическими частями | Связь clusters/disk; композиция. Операция создания не задана. |
| «пронумерованных» | R1 | Cluster, Disk | Cluster хранит number; область уникальности — Disk | Атрибут и ограничение нумерации. Операция перенумерации не задана. |
| «есть [на диске]» | R2 | Disk, Folder | Disk содержит сведения о размещённых папках | Связь folders/disk для всех папок диска. Это не команда добавления. |
| «именованные» | R2 | Folder, File | Каждый объект хранит собственное name | Атрибуты имени; переименование не предполагается. |
| «вложены» | R2 | Folder, Folder или File | Родительская Folder представляет непосредственное содержимое | Связи subfolders/parent и files/folder. Вставка и перемещение не заданы. |
| «список … хранится» | R3 | Folder, Cluster | Folder знает indexCluster; Cluster хранит содержимое | Ассоциация размещения списка. Она не делает папку владельцем жизненного цикла кластера. |
| «данные … хранятся» | R4 | File, Cluster | File знает dataClusters; Cluster хранит содержимое | Ассоциация размещения данных. Операция записи не задана. |

Действий без владельца нет: каждому предикату найдено структурное отражение. Основания для Service нет.

На этапе 7 по A4–A5 добавлены только операции наблюдения: Disk.findCluster, Disk.listFolders, Folder.listEntries, File.readData, Cluster.readContent. Ответственность распределена по данным: поиск номера знает Disk, содержимое папки — Folder, порядок частей файла — File, байтовую нагрузку — Cluster. Все эти методы сохраняют состояние; исходные требования не расширяются операциями изменения.
