# Именные группы в описании CRM

Именные группы приведены к начальной форме. Кандидат ещё не означает принятый класс: данные могут стать атрибутами, а процессы — операциями.

| Термин | Фрагмент и требование | Категория | Первичное решение |
| --- | --- | --- | --- |
| Система управления клиентами | «функций системы управления клиентами (CRM)», R1–R4 | Система в целом | Граница системы; не объект внутри собственной модели. |
| CRM | «(CRM)», R1–R4 | Название системы | Синоним границы системы. |
| Основная функция | «среди основных функций», R1–R4 | Абстрактное понятие | Не класс; вводит перечень целей. |
| Управление карточками клиентов | «управление карточками клиентов ManageClients», R1 | Процесс | Отложить для use case и операций. |
| ManageClients | То же, R1 | Имя функции | Имя use case, не класс. |
| Обработка заявки | «обработку заявки», R2 | Процесс | Отложить для use case и операций. |
| Проведение сделки | «проведение сделки», R3 | Процесс | Отложить для use case и операций. |
| Подготовка отчёта | «подготовку отчета», R4 | Процесс | Отложить для use case и возможного Service. |
| Менеджер по продажам | «Менеджер по продажам использует», R5; «Менеджеру ... назначается», R10–R11 | Роль человека | Кандидат SalesManager; также актор. |
| Работа | «в своей работе», R5 | Общее абстрактное понятие | Контекст деятельности, собственных данных нет. |
| Руководитель отдела | «выполняет руководитель отдела», R5; «один руководитель отдела», R11 | Роль человека | Кандидат DepartmentHead; также актор. |
| Отдел | В составе «руководитель отдела», R5, R11 | Организационная единица | Проверить отдельно, но не предполагать структуру организации. |
| Клиент | «Клиенты участвуют», R6; «его реквизиты», R7 | Роль участника | Кандидат Client; также актор. |
| Карточка клиента | «В карточке клиента ClientCard», R7, R10 | Учётный объект | Кандидат ClientCard. |
| ClientCard | То же, R7 | Заданное имя типа | Синоним «карточка клиента», не отдельный объект. |
| Реквизиты клиента | «указываются его реквизиты», R7 | Группа данных | Кандидат на атрибут или тип значения; структура не дана. |
| Заявка, поданная заявка | «поданные заявки Note», R7; «У заявки», R8–R9 | Учётный объект | Кандидат Note. |
| Note | То же, R7 | Заданное имя типа | Синоним «заявка». |
| Сделка, проведённая сделка | «проведенные сделки Deal», R7 | Учётный объект | Кандидат Deal. |
| Deal | То же, R7 | Заданное имя типа | Синоним «сделка». |
| Отчёт | «подготовку отчета», R4–R5 | Результат работы | Кандидат Report; проверить необходимость отдельного класса. |
| Дата | «дата и время», R8 | Простое значение | Кандидат на атрибут заявки. |
| Время | «дата и время», R8 | Простое значение | Кандидат на атрибут заявки. |
| Сообщение, текст сообщения | «текст сообщения», R8 | Значение, содержание заявки | Кандидат на атрибут заявки, а не подсистема переписки. |
| Ответ, текст ответа | «может быть указан текст ответа», R9 | Необязательное значение | Кандидат на атрибут заявки. |
| Он, его, эти функции, своя работа | Местоименные отсылки, R5, R7 | Местоимения | Разрешить отсылки к уже найденным понятиям; классы не создавать. |

Названия ClientCard, Note и Deal обозначают типы, а не конкретные экземпляры. Поэтому правило об исключении имён собственных не исключает соответствующие классы. «Сделка» рассматривается как сохраняемая запись о результате, а «проведение сделки» — как действие над предметной областью.
