# 8. Типы классов

| Класс | Тип | Идентичность / ответственность |
|---|---|---|
| Фактор | Entity | Устойчивое определение фактора. Равенство name само по себе не тождество; на двух этапах используется один reliability (D4). |
| Критерий | Entity | Один stability существует независимо от меняющегося набора метрик по этапам; идентичность не определяется этим набором (R3, D4). |
| Метрика | Entity | Общая метрика может входить в наборы разных критериев (R4). Сохраняется ссылка на одно определение; совпадение текста имени не используется как механизм идентификации (D4). |
| ЭтапРазработки | Entity | Именованный этап с собственной схемой: factorDescriptions и criterionSettings. Его идентичность сохраняется при изменениях схемы (D4). |
| ОписаниеФактораНаЭтапе | Entity | Идентичность — неизменяемая пара (factor, stage); набор criterionSettings может изменяться без создания нового описания (D3, D5). |
| НастройкаКритерияНаЭтапе | Entity | Идентичность — неизменяемая пара (criterion, stage); набор metrics изменяем (D3, D5). |

Выбор Entity для определений — явное предположение D4, а не утверждение о единственном возможном проектировании. В варианте полностью неизменяемых каталогов с установленным содержательным равенством могли бы применяться Value-object; исходное условие такой политики равенства не задаёт.

Методы configureCriterion/describeFactor не делают ЭтапРазработки отдельной Factory или Repository: его основная ответственность — контекст и согласованное состояние схемы конкретного этапа. Создание двух видов связанных объектов — вспомогательная операция этой Entity. Хранение коллекций само по себе не обосновывает инфраструктуру хранения.

Service не требуется: независимого процесса расчёта в условии нет. Самостоятельные Repository и Factory не вводятся, поскольку персистентность, поиск и сложное создание экземпляров не заданы. Несовместимых ответственностей, требующих разделения класса, не обнаружено.

Все шесть классов приняты по правилу этапа 4; в final-class-diagram.puml каждый помечен стереотипом Entity.
