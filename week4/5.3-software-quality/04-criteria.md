# 4. Проверка СИАОУТ

Правило: принять кандидата, если **Т = да ИЛИ сумма «да» ≥ 4 из 6**. «Не установлено» баллов не даёт. И означает изменение состояния, поэтому одно чтение имени не засчитывается. Для А учитывается также состояние связей, а не только примитивные поля.

| Кандидат | С: состояние | И: изменение через интерфейс | А: больше одного поля | О: больше одной операции | У: универсальность | Т: существенное требование | Сумма | Решение |
|---|---|---|---|---|---|---|---:|---|
| Фактор | да: name | нет: имя доступно только для чтения, изменение самого фактора не задано | нет: только name; обратные ссылки выводимы | нет: собственные операции не требуются | да: именованный фактор одинаково представляет любую группу критериев | да: R1–R2 требуют различать факторы и привязывать набор критериев к конкретному фактору; без этого понятия остаются не сгруппированные по факторам критерии | 3 | Принять по Т. |
| Критерий | да: name | нет: изменение определения не задано | нет: только name; обратные ссылки выводимы | нет: собственные операции не требуются | да: одно определение критерия применимо на разных этапах | да: R2–R3 требуют отличать критерий от метрик и связывать его разные наборы на разных этапах | 3 | Принять по Т. |
| Метрика | да: name | нет: изменение определения не задано | нет: только name; usages — обратная навигация | нет: операции измерения не определены | да: каждый экземпляр — переиспользуемое определение метрики | да: R3–R4 требуют общей метрики, включаемой в наборы нескольких критериев; строковые независимые копии не выражают эту общность | 3 | Принять по Т. |
| ЭтапРазработки | да: name, factorDescriptions, criterionSettings | да: configureCriterion и describeFactor меняют связанные конфигурации | да: имя и два множества связей | да: configureCriterion, describeFactor, factors | да: один интерфейс для анализа, реализации и других этапов | да: R2–R3, R6 требуют явного общего контекста обоих наборов | 6 | Принять. |
| ОписаниеФактораНаЭтапе | да: factor, stage, criterionSettings | да: setCriteria заменяет набор | да: две фиксированные ссылки и множество настроек | да: setCriteria, criteria | да: одинаковая структура для любой пары фактор–этап | не установлено: R2, R6 требуют контекстной связи, но отдельный класс не единственное её UML-представление | 5 | Принять по сумме; класс явно хранит состояние связи. |
| НастройкаКритерияНаЭтапе | да: criterion, stage, metrics | да: setMetrics заменяет набор | да: две фиксированные ссылки и множество метрик | да: setMetrics, metrics | да: одинаковый интерфейс для любой пары критерий–этап | не установлено: R3, R6 можно выразить также контекстным отношением без отдельного класса | 5 | Принять по сумме. |
| ПрограммноеСредство | не установлено: данных конкретного продукта нет | не установлено: операции продукта отсутствуют | не установлено: полей продукта нет | не установлено: операций нет | не установлено: интерфейс не определён | нет: R1–R10 требуют схему оценки, но не учёт экземпляров программных продуктов | 0 | Отклонить в данной области задачи. |
| Стандарт | не установлено: дано только имя источника | не установлено: изменения стандарта не заданы | не установлено: полей предметной модели нет | не установлено: операции отсутствуют | не установлено: интерфейс отсутствует | нет: фиксированная схема задачи не требует каталога или версий стандартов | 0 | Отклонить. |

Итог: шесть классов. Операции изменения наборов обоснованы D1 и проверкой сценариев, а не добавлены лишь ради порога. Строгая модель одного только исходного текста могла бы обойтись декларативными ассоциациями; явные классы связей выбраны для удобного представления зависимости от этапа.

ПрограммноеСредство и Стандарт отклонены в текущей области задачи. Если появятся учёт оценок конкретных продуктов, версионирование стандартов, формулы или фактические результаты измерений, эти кандидаты потребуют нового анализа. Сейчас это не пробел решения 5.3.
