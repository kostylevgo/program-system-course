## а. Классы методом именных групп

Из краткого описания выделяются **Фактор**, **Критерий**, **Метрика**, **ЭтапРазработки**. «Фаза» и «этап» здесь синонимы.

«Качество» — абстрактное свойство, «набор» — коллекция, «оценка» и «разработка» — процессы. Программное средство является предметом оценки, но задача не требует учёта конкретных продуктов. ГОСТ 28195—89 — источник схемы, а не отдельный класс этой модели.

Надёжность ПС — экземпляр Фактор; Устойчивость функционирования и Работоспособность — экземпляры Критерий. Анализ и Реализация — экземпляры ЭтапРазработки. Пять подписей в столбце «Метрика» — экземпляры Метрика.

Полный разбор именных групп и отклонённых кандидатов: [этап 1](01-nouns.md), [этап 2](02-filtering.md).

## б. Уточнение отношений

Простая цепочка «Фактор → Критерий → Метрика» недостаточна: она не показывает, какой набор относится к какому этапу. Вводятся два класса связей:

- **ОписаниеФактораНаЭтапе**: один фактор, один этап и непустой набор настроек критериев.
- **НастройкаКритерияНаЭтапе**: один критерий, один этап и набор метрик.

Таким образом, итоговая модель содержит **шесть классов**. Критерий в описании фактора доступен через настройку соответствующего этапа; дополнительная прямая связь с Критерий не нужна.

| Связь | Кратности |
|---|---|
| Фактор — ОписаниеФактораНаЭтапе | 1 — 0..* |
| ЭтапРазработки — ОписаниеФактораНаЭтапе | 1 — 0..* |
| Критерий — НастройкаКритерияНаЭтапе | 1 — 0..* |
| ЭтапРазработки — НастройкаКритерияНаЭтапе | 1 — 0..* |
| ОписаниеФактораНаЭтапе — НастройкаКритерияНаЭтапе | 0..* — 1..* |
| НастройкаКритерияНаЭтапе — Метрика | 0..* — 2..* |

Кратность справа означает число правых объектов для одного левого. «Несколько метрик» принято буквально как минимум две; непустой набор критериев — явно указанное предположение D2. Обратные 0..* допускают ещё не использованные определения в черновике. В готовой схеме каждый рассматриваемый фактор должен быть описан на каждом рассматриваемом этапе.

Обязательны уникальность пар (фактор, этап) и (критерий, этап), а также совпадение этапа описания с этапами всех его настроек. Метрика может входить в несколько наборов, в том числе у разных критериев. Это общие ссылки на объект, а не копии метрики.

Все отношения — ассоциации. Наследование и композиция условием не обоснованы. Полная диаграмма с атрибутами, операциями и ограничениями: [final-class-diagram.puml](final-class-diagram.puml). Подробные контракты: [этап 5](05-relations.md).

## в. Анализ: рисунок 14

В [диаграмме экземпляров анализа](10-analysis-objects.puml) присутствуют:

| Экземпляр | Класс / значение |
|---|---|
| stageAnalysis | ЭтапРазработки: Анализ |
| reliability | Фактор: Надёжность ПС |
| stability | Критерий: Устойчивость функционирования |
| factorAnalysis | ОписаниеФактораНаЭтапе: (reliability, stageAnalysis) |
| stabilityAnalysis | НастройкаКритерияНаЭтапе: (stability, stageAnalysis) |
| m1 | Метрика: Средства восстановления при ошибках на входе |
| m2 | Метрика: Средства восстановления при сбоях оборудования |

factorAnalysis включает stabilityAnalysis, а та использует **m1 и m2**. Получается ровно цепочка рисунка 14 с явно указанным этапом.

## г. Реализация: рисунок 15

Для того же reliability создаётся factorImplementation на этапе stageImplementation = Реализация. В него входят две настройки:

| Критерий | Настройка на реализации | Метрики |
|---|---|---|
| Устойчивость функционирования | stabilityImplementation | m1, m2, m3 |
| Работоспособность | abilityImplementation | m4, m5 |

| Метрика | Название |
|---|---|
| m1 | Средства восстановления при ошибках на входе |
| m2 | Средства восстановления при сбоях оборудования |
| m3 | Реализация управления средствами восстановления |
| m4 | Функционирование в заданных режимах |
| m5 | Обеспечение обработки заданного объёма информации |

[Диаграмма экземпляров реализации](11-implementation-objects.puml) содержит все связи и 12 объектов. reliability, stability, m1 и m2 обозначают те же определения, что в диаграмме анализа. Различаются именно контекстные описания и настройки: набор анализа остаётся {m1, m2}, а набор реализации становится {m1, m2, m3}. Ни рисунок 14, ни рисунок 15 не задаёт числовых значений метрик.
