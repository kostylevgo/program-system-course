# Этап 7. Сценарии и проверка покрытия

## Граница и акторы

Актор — **Доктор как пользователь системы**, по допущению A6. Это внешняя роль взаимодействия с программой; одноимённый предметный класс хранит сведения об участнике посещения. Пациент является получателем рецепта и участником предметной области, но самостоятельное взаимодействие пациента с интерфейсом не задано. Оператор/регистратор не введён без основания.

Цели: UC1 — учесть посещение (R1/R3), UC2 — выписать рецепт для пациента (R2), UC3 — просмотреть историю пациента (конкретизация R3 по A6). `include` и `extend` не используются: регистрация — предусловие UC2, а не обязательный вложенный вызов при каждой выписке. За одно зарегистрированное посещение по A3 можно выписать несколько рецептов.

## Проверка черновика и найденный пробел

| Сценарий | Что даёт черновик | Итог |
| --- | --- | --- |
| UC1 | `Посещение.создать` создаёт запись с участниками, временем и болезнью. | **G1:** не указан владелец общего сохраняемого набора записей. Само создание объекта не завершает учёт. |
| UC2 | `Посещение.выписатьРецепт` создаёт и связывает рецепт с данным посещением. | Покрыт для уже доступного объекта посещения. |
| UC3 | У посещения есть ссылка на пациента, но нет источника полного списка посещений. | **G1:** нельзя получить полную историю из изолированного объекта. |

Исправление G1: введён **РеестрПосещений**, сохраняющий посещения и выбирающий их по пациенту. Кандидат прошёл повторно этапы 1–5 (соответствующие строки добавлены в файлы `01`–`05`); СИАОУТ = 5, Т = да. Создание записи перенесено из Посещения в `РеестрПосещений.зарегистрировать`.

## Альтернативы и границы проверки

Исходный текст не задаёт альтернативных потоков. Ниже проверяются только следствия явно принятых допущений:

| Случай | Ожидаемый результат и покрытие |
| --- | --- |
| У пациента пока нет посещений | `получитьИсторию` возвращает пустой список; кратность 0..* допускает случай. |
| Повторный визит к тому же доктору | `зарегистрировать` создаёт новую идентичность; обе записи остаются в истории. |
| Два пациента с одинаковыми ФИО | Истории разделены по идентичности; ФИО не используется как ключ. |
| Выписка второго рецепта за тот же визит | Создаётся новый Рецепт; первый сохраняется; 0..* допускает случай. |
| Пустой список лекарств или пустое название | Предусловие `выписатьРецепт` не выполнено; рецепт не создаётся, состояние не меняется. |
| Посещение зарегистрировано, рецепт ещё не выдан | Запись остаётся учтённой с нулём рецептов. Медицинская причина невыдачи не моделируется. |
| У одного человека разные болезни в разных визитах | Болезнь хранится в Посещении, а не в одном изменяемом поле Пациента; история сохраняет контекст каждого визита. |

Сценарии проверены на уровне модели, без реализации информационной системы. Это проверка наличия данных, ответственности и допустимости состояний, а не испытание программного продукта.

## Открытые вопросы

Не определены исходным текстом: число болезней за визит, точный состав назначения, предел числа рецептов, оператор системы и правила исправления/удаления записей. Они закрыты допущениями только для учебной модели (A1–A7). Неразрешённых пробелов выполнения UC1–UC3 в этих границах нет. Ведение карточек, справочников и реальное хранение потребуют отдельных требований, если войдут в дальнейшее задание.

## Выполненная проверка артефактов

Проверки запущены через Python из `~/python-venvs/venv`; тестовые скрипты в файлы не сохранялись. Успешно проверены наличие 12 обязательных файлов, ссылки на требования и допущения, все восемь строк СИАОУТ, объявления и связи трёх диаграмм, соответствие итоговых классов решениям фильтрации, стереотипы и согласованность операций со сценариями.

На примерах состояния проверены кратности: повторные визиты одной пары участников, пациент без посещений, визит без рецепта, несколько рецептов за визит. Ограничения отклоняют рецепт без лекарств, пустое название лекарства и принадлежность одного рецепта двум посещениям. Независимый обзор модели не выявил содержательных противоречий; замечания к единообразию имён исправлены.

Локальные PlantUML, Java и Graphviz не обнаружены; SVG не создавались. Проверка структуры исходников не заменяет полную проверку синтаксиса и внешнего вида рендерером PlantUML.
