# 4. Проверка СИАОУТ

Принимаем класс, если **Т = да ИЛИ число «да» ≥ 4**. «Не установлено» не считается положительным ответом. Конструктор не считается изменением существующего состояния, а геттеры не добавляются ради количества операций.

| Кандидат | С: состояние | И: изменение через интерфейс | А: больше одного поля | О: больше одной операции | У: общность | Т: незаменимость для требования | Сумма «да» | Решение |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Пациент | да — обозначение человека | не установлено — управление профилем не задано | нет — требуется только строковое обозначение | не установлено — действия физического человека не интерфейс объекта программы | да — обозначение применимо к любому владельцу | нет — R1–R2 сохраняются через `Ежедневник.пациент` при A1 | 2 | Отклонить как класс, оставить атрибутом |
| Врач | да — обозначение автора рецепта | не установлено — учёт врачей не задан | нет — достаточно обозначения | не установлено — визит и выписка не функции R2 | да — обозначение применимо ко всем врачам | нет — R1 сохраняется через `Рецепт.врач` | 2 | Отклонить как класс, оставить атрибутом |
| Болезнь | да — название | не установлено — ведение медицинской истории не задано | нет — требуется только название | не установлено — медицинские операции вне R2 | да — название применимо к любой болезни | нет — R1 сохраняется через `Рецепт.болезнь` при A2 | 2 | Отклонить как класс, оставить атрибутом |
| Лекарство | да — текстовое обозначение препарата | не установлено — каталог не задан | нет — одно обозначение; доза и режим относятся к назначению | не установлено — каталоговых операций нет | да — обозначение применимо к любому препарату | нет — R1–R2 сохраняются через `Назначение.лекарство` при A3 | 2 | Отклонить как класс, оставить атрибутом |
| Ежедневник | да — пациент и состав записей | да — `записатьРецепт` меняет состав | да — идентификатор и пациент; отдельно связи с рецептами | да — `записатьРецепт`, `приёмыНаДату` | да — одинаковый интерфейс для независимых журналов | не установлено — R2 требует журнал, но не доказывает незаменимость отдельного класса; выбрана инкапсуляция по A1 | 5 | Принять по ≥ 4 |
| Рецепт | да — дата, врач, болезнь, назначения | да — `уточнитьРеквизиты`, `добавитьНазначение` | да — идентификатор, дата, врач, болезнь | да — указанные две операции | да — любой сохранённый рецепт по A2–A3 | нет — исходный R2 можно реализовать и без группировки по рецептам; она принята по A2 | 5 | Принять по ≥ 4 |
| Назначение | да — лекарство, доза, период, времена | да — `исправить` до планирования, `составитьПлан` создаёт события | да — лекарство, доза, начало, конец, времена, идентификатор | да — указанные две операции | да — любая постоянная ежедневная схема по A3–A4 | не установлено — R2 не задаёт структуру схемы; отдельный объект обоснован A3–A4 | 5 | Принять по ≥ 4 |
| ПриёмЛекарства | да — план, статус, факт | да — отметка, пропуск, сброс | да — идентификатор, плановое время, статус, фактическое время | да — `отметитьПринятым`, `отметитьПропущенным`, `сброситьОтметку` | да — все события в принятом режиме A4–A5 | не установлено — R2 допускает разные трактовки ежедневника; по A4–A5 это ключевая запись | 5 | Принять по ≥ 4 |

Решение о четырёх отклонённых классах предварительное относительно возможного расширения требований, но окончательное в принятом объёме. Для пересмотра нужны требования к нескольким профилям, справочникам, самостоятельным идентичностям и поведению этих понятий. Искусственные идентификаторы и операции изменения имени им не добавлялись.

Идентификаторы принятых классов служат различению записей (A6); без них у каждого принятого класса всё равно есть несколько содержательных составляющих состояния. `Ежедневник.приёмыНаДату` — значимая операция чтения, а не искусственный геттер для порога.
