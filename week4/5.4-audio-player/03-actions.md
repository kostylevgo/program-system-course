# Этап 3. Действия и владельцы операций

| Действие | Требование | Участники | Владелец / операция | Состояние и основание |
| --- | --- | --- | --- | --- |
| Состоять из компонентов | R1/R8 | Плеер, пять компонентов | Именованные связи композиции | Структурное владение; глагол не превращается в искусственный метод `consistOf`. |
| Обрабатывать ввод | R2/R7 | Пользователь, UI, команда | `UserInterface.submit(command)` | UI учитывает ожидающие ответы в `pending`. |
| Передать команду без ожидания результата | R7/A5 | UI, контроллер | `PlayerController.enqueue(command)` | Контроллер владеет очередью и создаёт обещание результата; возвращает `Future` немедленно. |
| Выполнить отложенную команду | R3/R7/A5 | Контроллер, менеджер, библиотека | `PlayerController.processNext()` | Меняет `queue`, `busy`; диспетчеризует по `Command.kind`. |
| Показать результат | R2/R7 | Контроллер, UI | `UserInterface.onCompleted(requestId, result)` | Удаляет запись `pending`, показывает результат/ошибку. Это callback завершения Future. |
| Реализовать воспроизведение | R3/A9 | Контроллер, библиотека | `PlayerController.play/pause/stop` | Контроллер владеет `playbackState`, `currentSource`, `activeHandle`. |
| Открывать и воспроизводить аудио | R1/R3/A2 | Контроллер, библиотека | `MediaLibrary.open/play/pause/close` | Библиотека владеет техническими ресурсами `handles`; механизм аудиоввода/вывода. |
| Найти установленный модуль | R6/R10 | Менеджер, модуль | `PluginManager.find(moduleId)` | Менеджер владеет индексом `installed`; поиск не создаёт модуль. |
| Загрузить модуль | R6 | Менеджер, модуль, компоненты | `PluginManager.load(id)` → `Plugin.load(ui, controller, media)` | Менеджер выбирает объект, модуль владеет своим `state` и runtime-ссылками. |
| Включить модуль | R6 | Менеджер, модуль | `PluginManager.enable(id)` → `Plugin.enable()` | `Plugin.state`: `LOADED → ENABLED`. |
| Выключить модуль | R6 | Менеджер, модуль | `PluginManager.disable(id)` → `Plugin.disable()` | `Plugin.state`: `ENABLED → LOADED`; пакет остаётся установленным. |
| Взаимодействовать с компонентами | R4 | Модуль, UI, контроллер, библиотека | Runtime-ассоциации; `Plugin.onEvent(event)` | Входные события обрабатываются только при `ENABLED`; конкретные расширения не заданы. |
| Получить установленные версии | R10 | Менеджер, все установленные модули | `PluginManager.installedVersions()` | Читает весь `installed`, независимо от `Plugin.state`. |
| Подключаться / отключаться | R8/R10 | Менеджер соединений, сервер | `ConnectionManager.connect/disconnect` | Меняет техническое состояние соединения. |
| Проверить обновления | R10 | Менеджер, менеджер соединений, сервер, база | `PluginManager.checkUpdates()` | Координирует чтение реестра и запрос; не меняет версии и состояния модулей. |
| Передать сетевой запрос | R10 | Менеджер соединений, сервер | `ConnectionManager.requestUpdates(versions)` | Управляет сетевым запросом и его Future; не сравнивает версии. |
| Ответить клиенту | R9/R10 | Сервер, база | `PluginServer.checkUpdates(versions)` | Сервер вызывает операцию каталога и возвращает данные. |
| Найти более новые версии | R9/R10 | База, описания версий | `ModuleCatalog.findUpdates(versions)` | Читает `releases`, выбирает максимальную версию для каждого установленного ID. |
| Сравнить версии | R10/A6 | Описание версии, установленная версия | `PluginDescriptor.isNewerThan(version)` | Чистая операция над неизменяемым значением. |

Все предметные действия получили владельцев. «Используя», «добавьте»,
«выделите», «определите» относятся соответственно к зависимости или к работе
проектировщика; отдельные методы приложения для них не нужны.

Публичный фасад менеджера не переносит к нему внутреннее состояние модуля:
запись в `Plugin.state` допустима только внутри операций самого `Plugin`.
