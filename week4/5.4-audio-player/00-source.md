# 5.4. Аудиоплеер: исходные требования

## Исходный текст

> 5.4. Аудиоплееры состоят из менеджера подключаемых модулей, пользовательского
> интерфейса, который обрабатывает пользовательский ввод, управляющего компонента,
> реализующего основную функциональность, и библиотеки мультимедиа. Загружаемые
> модули взаимодействуют с компонентами плеера.
>
> а. Выделите классы и определите отношения между ними, используя абстрактные типы
> данных (ADT) и метод Аббота.
>
> б. Для загрузки, включения и выключения подключаемых модулей добавьте операции
> и атрибуты к выделенным классам. Полагайте, что пользовательский интерфейс
> обрабатывает команды от пользователя асинхронно.
>
> в. Уточните описание аудиоплеера, чтобы в нем присутствовал менеджер соединений,
> и в системе в целом был сервер с базой доступных модулей. Менеджер модулей может,
> используя менеджер соединений, подключаться к серверу с целью проверки обновлений
> установленных модулей.

## Требования для трассировки

| ID | Требование |
| --- | --- |
| R1 | Аудиоплеер состоит из менеджера модулей, UI, управляющего компонента и библиотеки мультимедиа. |
| R2 | UI принимает и обрабатывает пользовательский ввод. |
| R3 | Управляющий компонент реализует основную функциональность плеера. |
| R4 | Загружаемые модули взаимодействуют с компонентами плеера. |
| R5 | Для выделения классов и отношений применяются ADT и метод Аббота. |
| R6 | Классы должны иметь атрибуты и операции загрузки, включения и выключения модулей. |
| R7 | UI обрабатывает команды пользователя асинхронно. |
| R8 | В состав плеера добавляется менеджер соединений. |
| R9 | В системе есть сервер с базой доступных модулей. |
| R10 | Менеджер модулей через менеджер соединений подключается к серверу и проверяет обновления установленных модулей. |

## Проектные предположения — не требования исходного текста

| ID | Принятое решение |
| --- | --- |
| A1 | У каждого работающего экземпляра плеера по одному экземпляру пяти компонентов; они принадлежат только ему и создаются/уничтожаются вместе с его runtime-контекстом. Это основание композиции. Установленные пакеты на диске имеют отдельный жизненный цикл. |
| A2 | «Библиотека мультимедиа» означает программную библиотеку открытия и воспроизведения аудио, а не медиатеку композиций. |
| A3 | `Plugin` представляет регистрацию установленного модуля в конкретном плеере, включая его runtime-состояние. Один менеджер учитывает все такие регистрации, даже незагруженные. В одном менеджере `moduleId` уникален; одинаковый пакет может использоваться разными плеерами через разные регистрации. |
| A4 | Состояния модуля: `INSTALLED` — установлен, но не загружен; `LOADED` — загружен и выключен; `ENABLED` — включён. Загрузка не включает модуль, выключение не выгружает. Повторные операции идемпотентны; включение незагруженного модуля ошибочно. Неуспешный переход сохраняет прежнее состояние. |
| A5 | UI немедленно возвращает `Future`, контроллер выполняет команды FIFO, по одной до завершения результата. Идентификатор команды позволяет сопоставить ответ и запрос. Ожидание сети приостанавливает очередь, но не UI. |
| A6 | Моделируются один логический сервер и одна его база; клиентов может быть много. Для одного `moduleId` версии имеют согласованный полный порядок. Сервер возвращает последнюю доступную версию, только если она новее установленной. |
| A7 | Загруженный модуль может удерживать ссылки на нужные ему UI, контроллер и библиотеку того же плеера: по `0..1` каждого вида. Не предполагается, что каждому модулю нужны все компоненты. При `INSTALLED` этих runtime-ссылок нет. |
| A8 | Список установленных модулей задан при восстановлении состояния плеера. Установка пакетов, их удаление, выгрузка и применение обновления не входят в задание. Проверка обновлений только возвращает сведения. |
| A9 | Для конкретизации основной функциональности выбраны воспроизведение URI, пауза и остановка. Плейлисты, форматы кодеков и детали аудиовывода не моделируются. |

## Уточнённое описание для пункта в

Аудиоплеер состоит из пользовательского интерфейса, управляющего компонента,
библиотеки мультимедиа, менеджера модулей и менеджера соединений. UI преобразует
ввод в команды и передаёт их в очередь контроллера, получая результат асинхронно.
Контроллер исполняет команды воспроизведения и обращается к менеджеру модулей
для загрузки, включения и выключения модулей. Менеджер учитывает все установленные
модули и делегирует переходы состояния соответствующему модулю. Загруженные
модули получают доступ к необходимым компонентам своего плеера.

В общей системе находится сервер, связанный с базой доступных версий модулей.
По команде проверки обновлений менеджер модулей получает пары «идентификатор,
установленная версия» из всего реестра и через менеджер соединений отправляет
их серверу. Сервер сравнивает версии с базой и возвращает сведения о более новых
версиях. UI асинхронно показывает результат или ошибку. Состояния модулей и их
установленные версии при этой проверке не меняются.
