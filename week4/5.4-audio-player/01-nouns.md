# Этап 1. Существительные и именные группы

Словоформы приведены к начальной форме. «Подходит» означает кандидата, а не
автоматически принятый класс. Составное обозначение конкретного механизма
рассматривается целиком: слово «библиотека» само по себе не доказывает наличие
коллекции объектов предметной области.

| Термин | Фрагмент / источник | Категория | Решение |
| --- | --- | --- | --- |
| Аудиоплеер, плеер | «Аудиоплееры состоят», «компонентами плеера», R1/R4 | Вещь, родовое понятие | Подходит. |
| Менеджер подключаемых модулей, менеджер модулей | «из менеджера подключаемых модулей», R1/R10 | Роль компонента | Подходит; это синонимы. |
| Пользовательский интерфейс | «пользовательского интерфейса», R1/R2 | Вид компонента | Подходит. |
| Пользователь | «команды от пользователя», R7 | Внешняя роль | Кандидат; вероятен актор вместо класса. |
| Пользовательский ввод | «обрабатывает пользовательский ввод», R2 | Абстрактные данные/процесс взаимодействия | Не самостоятельный класс; источник команды. |
| Управляющий компонент | «управляющего компонента», R1/R3 | Роль компонента | Подходит. |
| Основная функциональность | «реализующего основную функциональность», R3 | Абстрактное собирательное понятие | Не класс; уточняется операциями. |
| Библиотека мультимедиа | «библиотеки мультимедиа», R1 | Вещь: программный компонент по A2 | Подходит; не делаем класс только из слова «мультимедиа». |
| Подключаемый, загружаемый, установленный модуль | «Загружаемые модули», «установленных модулей», R4/R6/R10 | Вид вещи; признаки жизненного цикла | Один кандидат `Plugin`, не три подкласса. |
| Компонент плеера | «с компонентами плеера», R4 | Родовое/собирательное обозначение | Кандидат на обобщение; полезность проверяется отдельно. |
| Класс, отношение, ADT, метод Аббота, операция, атрибут | Формулировки пунктов а/б, R5/R6 | Термины метода проектирования | Не объекты предметной области. |
| Загрузка, включение, выключение | «Для загрузки, включения и выключения», R6 | Процессы | Отложить как операции и переходы состояния. |
| Команда | «обрабатывает команды», R7 | Вид информационного объекта | Подходит: неизменяемое сообщение в очереди. |
| Менеджер соединений | «присутствовал менеджер соединений», R8/R10 | Роль компонента | Подходит. |
| Соединение | Именная группа «менеджер соединений», R8 | Технический канал | Кандидат; отдельный объект может оказаться избыточным. |
| Система | «в системе в целом», R9 | Собирательное понятие/граница | Не класс; граница use cases. |
| Сервер | «был сервер», R9/R10 | Роль узла/службы | Подходит; модель серверной службы, а не железа. |
| База доступных модулей | «с базой доступных модулей», R9 | Вещь: хранилище | Подходит. |
| Доступный модуль | «база доступных модулей», R9 | Запись о распространяемой версии | Уточнить до `PluginDescriptor`; это не клиентский runtime-модуль. |
| Проверка обновлений, обновление | «с целью проверки обновлений», R10 | Процесс и его результат | Проверка — операция; результат — сведения о новой версии. |
| Версия, идентификатор, источник пакета | Уточнение смысла «обновлений установленных модулей», R10/A6/A8 | Значения, необходимые для сравнения и идентификации | Атрибуты; не отдельные сущности. |

«Команда» и «доступная версия модуля» имеют значение как передаваемые данные.
Их сохранение как ADT не требует моделировать физический поток, сокет или
строку базы отдельным классом.
